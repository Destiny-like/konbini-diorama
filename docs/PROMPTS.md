# 制作过程与提示词（凝练版）

> 这份文档记录这个场景是**怎么被造出来的**：工作流、拆解方式、每个子任务收到的提示词要点，以及几轮返工的真实原因。想复刻流程或改场景的话，看这一份就够。

---

## 0. 总体思路

一个人的会话窗口装不下一个 3500 行、20 万像素级细节的 3D 场景——所以把它当**工程**做，而不是当一次性代码写：

1. **先定接口，再并行开工**：把坐标、模块边界、材质/贴图工具先写死成一份契约（`CONTRACTS.md`），再让多个子任务同时实现，互不打架。
2. **每个子任务必须自己截图验收**：不接受「我写完了」，只接受「我拍了图，图里能看到什么」。
3. **集成方只做三件事**：拼接、验收、返工派单——不替子任务改代码。
4. **客观数字优先于形容词**：过曝像素占比、每帧角速度、draw call 数、雨声增益，这些能测的就不靠「感觉更好」。

## 1. 拆解：1 个调度 + 5 个并行实现 + 1 层验收

| 角色 | 拥有文件 | 职责 |
|---|---|---|
| 调度（我）| `src/main.js`、`src/core/*`、`build.mjs`、`shot.mjs`、`CONTRACTS.md` | 定契约、写共享工具、相机/后处理/交互状态机、集成与验收 |
| A | `src/world/street.js` | 底座、双街、斑马线、人行道、排水沟、停车位、积水反光、小巷 |
| B | `src/world/store.js` | 便利店外壳、玻璃幕墙、招牌、店内陈设、收银员、交互动画 |
| C | `src/world/props.js` | 贩卖机、自行车、路灯、电线杆+电线、护栏、公告牌等街景道具 |
| D | `src/world/atmosphere.js` | 天空、灯光与阴影、雨丝 shader、溅射、涟漪、雾 |
| E | `src/world/timeline.js` | 入场组装时间线（6 种装配模式）|

关键约束：**文件所有权互斥**。每个人只能改自己名下文件；缺工具在自己文件里写局部函数，不许去改 `core/`。这样 5 条线才能真并行。

## 2. 契约里最要紧的三件事

### 2.1 坐标系先钉死
```
底座 x,z ∈ [-12, 12]，顶面 y = 0，侧壁到 y = -1
南街 z ∈ [6,12]；东街 x ∈ [6,12]；人行道顶面 y = +0.14
便利店占地 x ∈ [-9, 3.5]，z ∈ [-9, 3.5]，正面贴 z = 3.5，东面贴 x = 3.5
一层净高 3.4（室内地面 0.15 / 吊顶 3.05）；二层 y ∈ [3.6, 6.3]
```
没有这段，五个模块拼起来必然穿模、浮空、错缝。

### 2.2 共享工具先行
`core/` 里只放四样：调色板 `P`、材质工厂 `M`（cel / interior / lit / glow / glass / outline）、程序化贴图工厂 `T`（沥青、地砖、招牌字、商品排面、海报、涟漪…）、几何工具 `U`（box / merge / inst / wire / mark）。
**所有贴图运行时用 canvas 生成**，仓库里零图片资源——这是「单文件离线可用」的前提。

### 2.3 装配动画用标注解耦
每个装配单元只打一个标签，时间线自己扫描：
```js
U.mark(obj, { order: 0.35, mode: 'drop' })
// mode: rise 从地下升 / drop 从空中落 / pop 缩放弹入 / grow 沿 Y 生长 / wipe 沿轴展开 / fade 淡入
```
好处：五个模块谁都不用知道时间线怎么实现，加物件也只需补一行标注。

## 3. 派给子任务的提示词模板（凝练）

每个 brief 都强制包含五段：**目标 / 边界 / 约束 / 验收标准 / 必须回报的证据**。以下是实际用的骨架：

```
你是「雨夜便利店微缩模型」的一名实现子代理。项目根目录：<path>

## 开始前必读
CONTRACTS.md + src/core/{palette,mats,tex,utils}.js（你可用的全部工具 P/M/T/U）

## 纪律
- 只能改自己名下文件；main.js / core/* / build.mjs 不许动；其他 worker 的文件不许动。
- 不许 npm install、不许引用外部图片与字体、不许新增 HTML 元素（零 UI）。
- 其他 worker 正在并行写各自文件：build 报错指向别人的文件就忽略重跑，绝不要去修。

## 自检链路（必须真的执行，并用 read_image 真的看图）
node build.mjs --dev --out out/<id>/index.html
node shot.mjs out/<id>/final.png '?t=9' out/<id>/index.html
node shot.mjs out/<id>/mid.png  '?t=3.5' out/<id>/index.html
（再用 chrome --dump-dom 读 title 里的 meshes= / tris= 数字）

## 必须包含（逐条列具体物件与坐标）
1. … 2. … 3. …

## 入场动画标注
列出每个物件该用的 order 区间与 mode

## 验收标准
- 默认机位下必须成立的三条视觉判据
- meshes / tris 预算

## 完成时必须回报
1. 改动文件与行数；2. 截图路径 + 你从图里确认了什么；3. meshes/tris；4. 与契约的偏差；5. 集成风险。
```

> 最有用的一条：**要求对方把「从图里看到了什么」写出来**。这逼着对方真的去看图，而不是交完代码就宣布完成。

## 4. 真实返工记录（这才是关键部分）

第一轮五个模块并行交付后，集成完能看，但一堆毛病。下面每一行都是「现象 → 定位方式 → 修法」，提示词的进化全在这里：

| 现象 | 怎么定位的 | 修法 |
|---|---|---|
| 东侧马路上空浮着一块灰色薄板 | 加 `?hide=street` / `?only=street` 逐模块隔离渲染，板子只在有 street 时出现 | 根因不是 y 错，而是人行道 Box 长度算错（21.5 应为 15.5），探出底座 3m |
| 店门口一团纯白过曝 | 逐模块关灯对比，发现与 atmosphere 无关 | 店内自发光 + 4 盏点光太强；压低自发光、点光按像素测量校准 |
| 店内像「发光货架飘在黑洞里」 | 近景截图 + 关掉外景灯单看 store | 地面/吊顶/侧墙改用自发光材质、加天花灯槽、点光回升 |
| 玻璃把暖黄压成灰白 | 看材质：玻璃 tint 是 0xbfe3ff（淡蓝） | 幕墙玻璃 tint 改暖中性、opacity 0.10 → 0.06 |
| 招牌字被 bloom 吃掉 | 截图取玻璃区均值 RGB | lit boost 1.6 → 1.05，bloom 0.62/0.72/0.72 → 0.42/0.55/0.86 |
| 入场动画第一帧就有悬空发光片 | 拍 `?t=0` | 有对象漏打 asm 标注，按组补齐 |
| 走到柜台停不下来 / 一步跨过 | CDP 连点采样 s 轨迹 | 加「收银台靠站」：靠近时把 sTarget 夹到柜台参数 |
| POS 屏点不中 | 投影热点中心 → 发现点在了屏幕下方 0.22m | 加 46px 屏幕空间容错命中 |
| 「靠近雨声变小」没生效 | 打点读增益 | 阈值设在 4–17m，但俯瞰相机最近只有 18m，够不到；映射改为 30→8m |

## 5. 用客观数字验收的例子

不靠「看起来更丝滑」，而是把这些数字测出来：

- **过曝**：`>245` 像素占比，要求 < 2%（实测收银台 0.16%、货架 0.89%）
- **转向平滑度**：每帧相机方向角变化（直道 1.16°/帧，连过 90° 弯 3.52°/帧，60fps 下约 211°/s）
- **位移缓动**：单步 s 轨迹逐 110ms 采样，确认是加速→减速而不是瞬移
- **自动播放**：CDP 实时采样 `progress` 0.31 → 0.89 → 1.0，同时确认相机从起始位插值到终位
- **交互**：CDP 真点按钮，读 `mode / door / indoor / s` 状态机字段
- **雨声**：读 `gain / lowpass / 距离`，验证 40m → 0.338、15m → 0.194、店内 → 0.050 + 低通 769Hz

## 6. 几个刻意的取舍（也是提示词里写死的）

- **单文件 HTML**：three.js 用 esbuild 打成 IIFE 内联，双击离线可用。代价是改代码要重新打包。
- **不做实时反射**：湿地面是「深色高光水洼 + 加法混合倒影条」伪造的，Reflector 会让整景 draw call 翻倍。
- **不只靠实时 GI 照亮店内**：室内大面用自发光材质 + 天花灯槽，点光只做点缀。
- **雨在入场动画收尾才落下**（order 0.88）：刻意编排，不是漏做。
- **人物只有一个店员**：最初设定是「不要人物」，后来因为交互需求加了收银员，仍保持低模三渲二、无写实五官。

## 7. 想复刻这套流程

1. 先写 `CONTRACTS.md`：坐标 + 模块边界 + 共享工具 API + 验收判据。这一步花的时间，会在集成阶段十倍赚回来。
2. 把 `core/` 写扎实（材质/贴图/几何工具），让子任务不需要发明轮子。
3. 文件所有权互斥，然后**并行**派单。
4. 每个子任务自拍自看，回报必须写「从图里看到了什么」。
5. 集成方用**隔离渲染**（`?only=` / `?hide=` / 关灯对比）定位问题归属，不猜。
6. 返工要给**具体证据 + 具体改法**，不要给「再优化一下」。
7. 能测的都用数字验收。
